# Notas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página Notas que mostra, por matéria cursando, pontos obtidos, bônus de simulados, quanto falta para o mínimo e pontos em jogo, com lançamento de nota em provas/trabalhos concluídos.

**Architecture:** Colunas novas em `materias` (`nota_minima`, `nota_total`), `provas` (`valor`, `nota`, `simulado`) e `trabalhos` (`valor`, `nota`). A nota é lançada pelos `PATCH` existentes; um blueprint novo `GET /api/notas` entrega os dados crus; os cálculos ficam em `notas-utils.js` (funções puras, `node --test`).

**Tech Stack:** Python 3.14, Flask 3, PyMySQL, pytest; MariaDB 10.4 do XAMPP (porta 8000); JS puro em scripts clássicos; `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-16-notas-design.md`

## Global Constraints

- Números de pontos: ≥ 0, até 1 casa decimal, até 9999,9. Coluna `DECIMAL(6,1) NULL`.
- Na resposta JSON, pontos são **número** (`float`) ou `null`, nunca string. (O Flask serializa `Decimal` como string; converter antes.)
- Exibição em pt-BR: vírgula decimal, sem ",0" em inteiros (`7,5`, `30`).
- Contas no frontend em décimos inteiros (×10) para evitar erro de ponto flutuante.
- `bd.sql` continua podendo rodar de novo sem apagar dados (`ADD COLUMN IF NOT EXISTS`).
- Mensagens de erro da API em português, formato `{erro}` com 400, como já é hoje.
- Interface: mesmo tema escuro, ícones SVG (sem emojis), componentes de `ui.js`/`componentes.css`.
- Comandos: pytest `.venv\Scripts\python -m pytest backend/tests -q`; JS `node --test tests/`.

## Review Focus

1. **Decimal como string no JSON:** `valor`/`nota`/`notaMinima` chegando como `"30.0"` faz o frontend concatenar em vez de somar. Teste em Tasks 2 e 3 confere `isinstance(..., float)`.
2. **"Desfazer" do toast depois de lançar nota:** desmarcar (`{concluido: false}`) item com nota deve funcionar e manter a nota; mandar `{concluido: false, nota: 5}` deve ser recusado. Teste na Task 3.
3. **Matéria antiga sem mínimo/total:** `PATCH` só com `nome` continua funcionando; `PATCH` com só `notaMinima` maior que o total gravado é recusado. Teste na Task 2.
4. **Somas com decimais:** 0,1 + 0,2 deve dar 0,3 e "Faltam 0,5 ponto" (singular abaixo de 2). Teste na Task 5.
5. **Bônus maior que a folga até o total:** 97 + 8 com total 100 dá final 100; e `falta > emJogo` com `final ≥ minimo` é "Aprovado", não "Não dá mais". Teste na Task 5.

**Interfaces:**

- Produces:
  - `validar_item(dados, campo_data, parcial=False, aceita_simulado=False)` — passa a tratar `valor` (obrigatório no `POST`, `positivo=True`, rótulo `"O valor"`), `nota` (só no `PATCH`; número via `validar_pontos(..., "A nota")` ou `None`; no `POST` → 400 `"A nota só pode ser lançada depois de concluir."`) e, com `aceita_simulado`, `simulado` (booleano; senão 400 `"O campo simulado deve ser verdadeiro ou falso."`).
  - `checar_nota(atual: dict, dados: dict) -> None` em `validacao.py` — `atual` é o item formatado (chaves `valor`, `nota`, `concluido`), `dados` são as colunas limpas. Calcula o estado após o `PATCH` e lança `ErroValidacao`:
    - nota numérica e item não concluído → `"Só é possível lançar nota depois de concluir."`
    - nota numérica e valor `None` → `"Defina o valor antes de lançar a nota."`
    - nota > valor → `f"A nota não pode passar do valor ({fmt_pontos(valor)})."`
    - só `valor` mudou e ficou menor que a nota gravada → `f"O valor não pode ser menor que a nota já lançada ({fmt_pontos(nota)})."`
    - Só checa a nota quando `nota` vem no `PATCH` ou quando `valor` muda; desmarcar concluído com nota gravada **não** é erro (a nota fica guardada).
  - Resposta de provas: `+ valor, nota, simulado`; de trabalhos: `+ valor, nota`. Números via `pontos_json`.

### Task 5: `notas-utils.js`
